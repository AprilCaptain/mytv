# 画质与播放失败排查

检查日期：2026-10-16。以下结果来自项目原有公开请求链路、独立解码抽样和浏览器实播，不代表所有设备、集数或时段。

## 本次反馈的两个例子

配置「综合片库」，A123TV《遮天》2024 条目 `/v/zhetian2.html`，第 01 集：

| 线路 | 本次结果 | 判断 |
| --- | --- | --- |
| 线路219 · 1080p | 独立解码及浏览器均为 1920×1080，H.264 / AAC；首个 3 秒分片约 2.27 Mbps，浏览器最近分片约 2.3 Mbps；只有一个画质档位 | 没有发现播放器把分辨率降成 720p。像素尺寸不能说明原生制作分辨率、压缩质量或是否经过上游放大，不能仅凭尺寸保证画面细节 |
| 线路222 · 720p | 播放页和选集可读取，媒体域名 `vodcnd09.kunyu.com.cn` 返回 ENOTFOUND；首集与最新集均未取得可解码媒体 | 本次是外部媒体服务的 DNS / 可达性问题，不能靠更换本机解码器修复；不猜测替换域名，不绕过网络或证书检查 |
| 线路224（补查） | 播放列表标注 1080×608，首分片约 0.58 Mbps，可读取媒体 | 作为可达性补充，不是更高清的保证 |

另查 A123TV《遮天》2023 条目的线路154，虽然站点标注 1080p，首集实际解码为 **1280×720**。量子《遮天动画版》第185集实际为 **1920×818**；魔都《流浪地球2》样本仍可通过媒体代理解码为 **3840×1608**。这些结果说明：站点标识可能与实际画面不一致，也没有证据显示本项目对所有源统一缩小分辨率。

本项目服务端只转发媒体与改写播放列表，HLS.js 在浏览器中转换媒体封装并交给浏览器解码，没有服务端视频转码、缩放或 AI 增强。压缩、低码率、放大后的低清素材，都可能装在 1080p 视频中；播放器无法凭空恢复原始细节。浏览器或设备不支持某种编码通常表现为失败、黑屏或卡顿，不能据此解释本次所有模糊画面。

## 当前提供的能力

- 播放器下方显示「实际 宽×高」，取自浏览器解码尺寸。
- 展开「播放信息」可查看实际尺寸、播放列表标注、检测到的视频 / 音频编码，以及最近最多 3 个媒体分片的估算码率。分片码率不等于整部影片的平均码率，也不是网络下载速度。
- 多档 HLS 在控制栏提供「优先清晰」「自动匹配」和具体档位。默认优先可用的高尺寸档位，自动模式可随网络变化调整；档位尺寸及标注码率来自播放列表，以实际解码尺寸为准。只有一档时显示灰色「片源画质」，需要更清晰时应更换线路或来源。
- 失败提示区分域名解析、连接超时、地址失效、访问被拒绝、视频编码、视频密钥及分片错误；需要时可展开简短详情，不打印临时媒体 URL。
- 手动选择的线路失败后可点击「尝试备用线路」，沿用同集进度，自动尝试最多另外两条同集线路。跳过缺集线路，不把缺集计作已尝试的可播放线路，不自动跳到其他集。
- 解析播放地址约 15 秒、无首帧约 16 秒或持续缓冲约 20 秒时提示并按既有自动模式尝试备用；主动暂停、自动播放被浏览器阻止及释放旧播放器时不会继续误判。

## 兼容性修复

1. HLS 播放会话建立前检查顶层播放列表，提前拒绝返回网页、错误信息或失效地址的线路。首份较小列表短时复用，避免立即重复下载；这不代表已证明全部分片都可播放。
2. 主列表中的变体、独立音轨等子列表带签名的类型标识。即使子列表没有 `.m3u8` 扩展名、被标为 `text/plain`，也继续按 HLS 改写转发；之前可能将它当普通媒体而拒绝。类型标识参与 HMAC 校验，不能篡改来绕过签名。
3. 网页适配器的播放预检支持被拆成多个网络块的 HLS 文件头，不把半个文件头误判为无效播放列表。

沿用公网 / DNS / TLS 检查、跨域凭证限制、媒体 MIME 与大小限制，没有增加 FFmpeg、数据库或运行依赖。独立解码工具仅用于开发抽样，不是用户启动所需组件。全部检查均不修改真实用户的观看历史。

## 验证范围

回归覆盖扩展名缺失的 HLS 子列表、类型标识篡改、失效列表、DNS 错误提示、备用线路缺集匹配、画质排序、首帧及缓冲截止时间、手动暂停、旧播放器释放和菜单自动隐藏。浏览器针对 219 实播、222 明确报错与同集换线恢复作额外检查。

另外使用本机生成的测试视频，在隔离服务中验证多档 HLS：默认 1280×720，手动降到 640×360，再切回高档；播放位置持续前进，没有从头重播。测试子列表刻意省略扩展名并使用 `text/plain`，确认上述兼容修复能完成实际解码。这些生成视频和测试网络映射不随产品发布，也不会对外放宽网络校验。
